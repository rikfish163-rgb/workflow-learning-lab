# 面试准备

项目研究工作流 Agent 的错误恢复与经验复用。可以沿着模型生成动作、工具执行、记录观察、检查终态、提取经验、对照评测这条调用链介绍实现。

## 训练

SFT 样本保留完整历史，只对最后一条助手动作计算监督损失。历史位置的 label 为 -100，历史仍参与前向计算。NF4 压缩冻结基座的表示，LoRA 更新低秩适配器。训练完成 86 次更新，训练损失本身不能代替任务成功率。

## 纠错

两个定向实验人为省略批量写入的最后一个目标，再让模型根据当时可见的历史继续执行。核验修复动作是否指向遗漏目标，是否使用相同接口和其他参数，以及返回是否与参考一致。官方整题评分和这些局部动作核验分别记录。

后续四个受控工作流使用真实 AppWorld API。工具层在进入后端前拒绝一次写入，模型自行发出同参纠正，并读回同一资源的目标状态。四项均通过独立审计，共 68 次模型生成、64 次实际 API 调用。

## 经验与评测

提取器只能读取允许的可见证据。候选经过内容筛查和模型审查后冻结为配对评测的一臂输入。布尔事实提取返回弃权，后续用匿名顺序证据生成一条通过复审的候选经验。两次各调用一次，结论限定在实际观察。

每题分别运行无经验与有经验两臂，使用新环境及相同模型、随机种子和预算。统计按场景处理相关性，unknown 保留为未知。自编 9 场景、27 对已全部完成，两臂通过的是同样的 3 个任务。旧官方面板中断后保留原结果，经授权另冻结未使用的 9 场景、27 对，54 个分支全部取得官方评分，两臂均为 0/27。这条经验没有显示出成功率收益。

## 可用于简历的三条

- 搭建 AppWorld Agent 执行和独立评分链路，限制模型通过预绑定 API 发起 JSON 工具调用。实现写入前拒绝注入和同资源读回核验，完成 4 个受控工作流的真实工具纠错审计。
- 将前读、拒绝、同参纠正和后读转成匿名顺序证据，接入经验生成、结构筛查和原文复审。冻结 1 条通过复审的候选经验，供对照评测的经验臂在首轮使用。
- 按场景隔离来源与评测任务，固定模型、种子、预算和初始状态，完成自编及官方独立面板各 9 场景、27 对有无经验评测。官方面板取得 54 份独立评分并核验 14 次 GPU 释放，两臂均为 0/27，保留负结果与完整成本记录。

## 应能说明的细节

- 一条 Python 动作可以发起多个工具请求，因此动作数与请求数分别计数。
- 模型自报完成和任务最终状态满足要求是两种信号，来源实验中已有二者不一致的记录。
- 额外续跑后成功需要计入额外成本，不能当成初试成功。
- 追加上下文经验不会修改模型参数。LoRA 微调涉及梯度与参数更新。
- 受控恢复描述具体条件下的行为。候选通过复审后，仍需按完整配对终态评分验证其效用。
- 官方 003 两臂自报完成分别为 10/27 和 18/27，最终评分却全部未通过。自报完成增多不能写成可靠性提升。
- 全零差值会产生退化的 `[0, 0]` 区间，不能证明总体等效。全失败也限制了该面板区分方法优劣的能力。
- 75 秒单次生成限制是两臂共同登记的预算，按 token 边界停止，并非硬实时保证。本轮与历史预算不同，分别报告。
- 没有经验通过效用门槛，因此未开展由该经验触发的蒸馏或参数更新。多轮 RSI 尚未验证。

个人简历中的职责和技术掌握程度应按实际参与情况填写。阅读代码后，建议能现场解释一次模型调用如何经过预算检查、执行器、轨迹记录和评分，再说明异常如何影响结果统计。
