# 面试准备

项目研究工作流 Agent 的错误恢复与经验复用。可以沿着模型生成动作、工具执行、记录观察、检查终态、提取经验、对照评测这条调用链介绍实现。

## 训练

SFT 样本保留完整历史，只对最后一条助手动作计算监督损失。历史位置的 label 为 -100，历史仍参与前向计算。NF4 压缩冻结基座的表示，LoRA 更新低秩适配器。训练完成 86 次更新，训练损失本身不能代替任务成功率。

## 纠错

两个定向实验人为省略批量写入的最后一个目标，再让模型根据当时可见的历史继续执行。核验修复动作是否指向遗漏目标，是否使用相同接口和其他参数，以及返回是否与参考一致。官方整题评分和这些局部动作核验分别记录。

## 经验与评测

提取器只能读取允许的可见证据。候选需要经过内容筛查和模型审查，随后才能冻结为配对评测的一臂输入。实际提取调用目前返回弃权，27 对任务尚未执行。

评测设计固定 9 个来源之外的训练场景，每个场景 3 题。每题分别运行无经验与有经验两臂，使用新环境及相同模型、随机种子和预算。统计按场景处理相关性，unknown 保留为未知。

## 应能说明的细节

- 一条 Python 动作可以发起多个工具请求，因此动作数与请求数分别计数。
- 模型自报完成和任务最终状态满足要求是两种信号，来源实验中已有二者不一致的记录。
- 额外续跑后成功需要计入额外成本，不能当成初试成功。
- 追加上下文经验不会修改模型参数。LoRA 微调涉及梯度与参数更新。
- 两例受控恢复只能支持具体条件下的行为观察。经验是否有效仍需要完成对照评测。

个人简历中的职责和技术掌握程度应按实际参与情况填写。阅读代码后，建议能现场解释一次模型调用如何经过预算检查、执行器、轨迹记录和评分，再说明异常如何影响结果统计。
